# Privacy Impact Assessment — Hippo

## 1. Executive summary

Hippo is a surgical case-logging and Competence-by-Design (CBD)
assessment platform built specifically for surgical residents,
fellows, and program directors. The system stores **case-level
metadata** (procedure, role, autonomy level, attending name,
operative duration), **assessment data** (EPA observations,
O-SCORE evaluations, milestones), and **scheduling data** (rotation
blocks, pre-op briefs).

**Hippo does NOT collect, store, or process any of the following:**

- Patient names, MRNs, PHIN numbers, or any other patient identifier
- Patient dates of birth (only age bins: under-18 / 18-30 / 31-45 /
  46-60 / 61-75 / over-75 / unknown)
- Free-text patient narratives unscreened for PHI
- Clinical images, radiology, pathology, or any other imaged identifiers

This deliberate design choice means Hippo holds **no Personal Health
Information** about patients in the meaning of PHIA, PIPEDA, or HIPAA.

The personal information Hippo *does* hold is about its **users**
(residents, fellows, attendings, programme staff): name, email,
institution, profile photo (optional), training year, plus their case
log content.

## 2. Scope

This PIA covers the production deployment of Hippo at:
`https://hippomedicine.com` and any institution-specific subdomain
(e.g. `umanitoba.hippomedicine.com`).

## 3. Information categories

### 3.1 User personal information

| Category | Source | Purpose | Retention |
|---|---|---|---|
| Name | User input at signup | Display on profile, EPA observation labels | Until account deletion |
| Email | User input at signup | Authentication, notifications | Until account deletion |
| Profile photo | User upload (optional) | Avatar | Until user deletes / replaces |
| Specialty + training year | User input at onboarding | Personalised content, programme stats | Until account deletion |
| Institution | User input at onboarding | Programme membership | Until account deletion |
| IP address | Captured at signup, login, and policy-acceptance only | Security audit + click-wrap evidence | 7 years (legal evidence) |

### 3.2 Case log content (user-authored, no patient identifiers)

| Category | Source | Purpose | Retention |
|---|---|---|---|
| Procedure name + category + approach | Manual entry / dictation | Case log | User-controlled (delete or export anytime) |
| Role + autonomy level | Manual entry | EPA + competency mapping | User-controlled |
| Attending name (label only) | Manual entry | Sign-off routing | User-controlled |
| Hospital / OR site | Manual entry | Case attribution to rotation block | User-controlled |
| Operative duration | Manual entry / dictation | Analytics | User-controlled |
| Patient age bin | Manual entry | Specialty mix analytics | User-controlled |
| Diagnosis category | Manual entry | EPA mapping | User-controlled |
| Outcome + complication category | Manual entry | M&M analytics | User-controlled |
| Resident reflection | Manual entry | Personal learning log | User-controlled |
| Operative dictation | Generated by Hippo from structured inputs | Case-note draft | User-controlled |

**No patient identifier is ever stored.** Inputs are pre-screened by a
PHI-pattern detector that flags anything resembling a name, MRN, PHIN,
DOB, or postal code with > 6 digits before save. The flagged content
must be redacted by the resident before the form will submit.

### 3.3 Assessment data

| Category | Source | Purpose | Retention |
|---|---|---|---|
| EPA observations | Resident submits, attending signs | CBD assessment trail | 25 years (Royal College retention) |
| O-SCORE evaluations | Same as above | Same | 25 years |
| Milestones / personal records | Auto-derived from cases | Gameification | Until account deletion |
| CC review notes + decisions | Programme committee members | Promotion / remediation evidence | 25 years (programme record) |

## 4. Lawful basis (PIPEDA + provincial equivalents)

- **Section 7 PIPEDA** — collection necessary to deliver the
  professional educational service the user signed up for.
- **PHIA (Manitoba) §22(1)(a)** — not applicable: Hippo is not a
  trustee of personal health information because it does not collect
  any.
- **PHIPA (Ontario) similar reasoning** — Hippo is not a health
  information custodian.
- **Consent** — explicit, informed, opt-in click-wrap captured at
  signup and re-captured every time a policy materially changes
  (`LegalAcceptance` model, indexed by `(userId, policyKey, version)`).

**Cross-border note:** All sub-processors are US-based. For Canadian
universities subject to provincial cross-border data restrictions, a
Canadian-region Supabase deployment is available (`ca-central-1`) and
will be the default for any institution that requests it.

## 7. User rights (PIPEDA Schedule 1)

Every Hippo user can, at any time:

- **Access** — download a copy of all their data via *Settings →
  Export data*. Returns JSON + CSV.
- **Correct** — edit any field on any case, profile, EPA observation,
  pearl. The audit log preserves the prior state.
- **Withdraw consent** — *Settings → Delete account* removes the user
  record + cascades to all owned data within 30 days. Programme-level
  EPA records the resident's attendings signed off on are retained for
  the 25-year Royal College assessment-record period (anonymised:
  `[redacted by user request]` replaces the resident's name) — the
  resident is informed of this at deletion time.
- **Withdraw from training data** — *Settings → AI preferences* opts
  out of any contribution to dictation-style training data. Default
  is opt-out; opting in is fully informed.
- **Complain** — to the institutional privacy officer or directly to
  the relevant provincial commissioner. Hippo cooperates fully with
  any commissioner investigation.

## 8. Risks and mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Patient identifier leakage via reflection / notes | High | Pattern-based PHI detector at input; auto-redact before save; QA-tested against names, MRNs, PHINs, DOBs, postal codes |
| Unauthorised access to another resident's case log | High | Row-level security on every table keyed to `auth.uid()`; service-role key never reaches the client |
| Stolen / leaked anonymous Supabase key | Medium | RLS forces all reads through user-context policies; an anon key cannot read another user's rows even if exfiltrated |
| Dictation API call leaking sensitive content to LLM provider | Medium | Pre-call PHI scrubber; prompt-injection-resistant framing; no conversation persistence on provider side |
| Long-term retention of finalised CC reviews | Low | Required by Royal College accreditation; explicit user notice at signup and at deletion |
| Sub-processor breach | Medium | DPAs in place; Hippo notifies users within 72 h of any sub-processor breach; sub-processors monitored quarterly |

## 9. Outstanding gaps (transparent disclosure)

- **SOC 2 Type II** is targeted for Q4 2026; SOC 2 Type I expected Q3 2026.
- **HIPAA Business Associate Agreement** is available on request but
  not yet templated — institutions deploying outside Canada should
  request the BAA explicitly.
- **Penetration test** by an external assessor is scheduled annually;
  the most recent report is available under NDA on request.
